# Hyperflip

Sports parlays on HyperEVM testnet (chain 998). Pick outcomes from different games,
request a signed quote, and mint a ticket whose payout is fixed on-chain.

The initial app supports sports only. Legs from the same game or question are
refused. Pricing multiplies the leg probabilities, applies the configured house
edge, and enforces the contract's payout floor and the writer's exposure caps.

## Repository

| Path | Purpose |
| --- | --- |
| `src/`, `test/` | Solidity vaults, settlement verification, and tests |
| `writer/` | Quote signing, pricing, exposure limits, and ticket resolution |
| `keeper/` | Core balance verification and outcome settlement |
| `web/` | Next.js landing page and trading app |
| `registry/` | Public testnet deployment and market metadata |
| `tools/`, `ops/` | Market rotation and service operations |

The full correlation implementation, research, and tests are preserved on
`archive/correlation-research` at `f0db775`. That branch is outside the initial
sports app. Historical vault metadata remains in the registry for settlement
recovery; the public market API and frontend expose only sports.

## Install and verify

Use Node.js 22.22.2 (see `.nvmrc`) and Foundry v1.8.0, matching CI. From the repo root:

```bash
git submodule update --init --recursive
for project in keeper writer web; do
  npm ci --prefix "$project"
done
bash scripts/verify.sh
```

The verification script runs Solidity formatting, build and tests, service
typechecks and tests, the web build and tests, and the tool checks. It supplies
fixture endpoints for the web build. No private `.env`, signer, funded wallet, or
running service is needed. Installation and the initial Google-font build need
network access. Tests use local fixtures rather than live market prices.

## Run the frontend

Create `web/.env.local` from `web/.env.example` if it does not already exist.
Set `NEXT_PUBLIC_WRITER_URL` to your writer endpoint, then run:

```bash
npm run dev --prefix web
```

Open `http://localhost:3000`. `/build`, `/positions`, and `/pricing` are the trading
routes. An empty Privy app ID uses the existing wallet-connector fallback.
The frontend can render without a writer; markets and quotes require a reachable
writer. Wallet actions require testnet funds and a valid invite code.

## Run your own services

Create a root `.env` from `.env.example`, then fill in the wallet addresses,
service keys, deployment address/block, invite codes, and risk limits. Both
services read this root file, regardless of the working directory. Never put
private keys in `web/.env.local`; `NEXT_PUBLIC_*` values ship to the browser.

```bash
forge build
npm start --prefix writer
```

Run `npm start --prefix keeper` in another terminal. The keeper key must match
the keeper stored in each OutcomeVault. The quote signer and bankroll address
must match the ParlayVault deployment; arbitrary keys cannot operate the shipped
deployment. A separate deployment needs its own market registry and matching
frontend configuration.

The writer uses `out/` ABIs generated by `forge build`. It refuses quotes until
on-chain exposure is loaded. An unset `RESEND_API_KEY` disables email signup;
configured invite codes still work. Keep one writer per deployment: reservations
are process-local and are not shared between replicas.

See [DEPLOY.md](DEPLOY.md) for persistent state, RPC requirements, rotation, and
service operations. Production deployment and contract broadcasts are separate
from local verification.
