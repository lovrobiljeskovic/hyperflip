Research timeline

1. Problem framed

The current table was recognized as hypothesis-led. The goal became comprehensive, defensible joint probabilities that improve venue trust, with hard data preserved outside conversational context.

2. Project architecture inspected

The system was mapped as a HyperEVM application with a HyperCore seam: HyperEVM holds escrow, slips, and settlement truth; HyperCore supplies live outcome books and status; the writer signs off-chain quotes; the keeper relays settlement state.

3. Current correlation engine inspected

The writer uses global/cluster/underlying positive factor loadings and a Gaussian hierarchical copula. The table describes the loadings as hand-set. The rho band prices from a house-favorable uncertainty endpoint.

4. Venue-native observations compared

Exploratory 30/90/180-day correlations were computed from Hyperliquid hourly candles. Several differed materially from current implied values, and some changed sign by window. This established that a static table can be stale, but did not by itself validate a replacement model.

5. Statistical approach selected

Dynamic, shrunk dependence was preferred over one full-history sample. Tail dependence, asymmetric regimes, proper probability scores, and session alignment were included as explicit requirements.

6. Historical RPC question investigated

A generic HyperEVM archive RPC was rejected as a substitute for historical HyperCore state. The repository already warns that pinned precompile calls can return live Core values. Managed HyperCore history remained an option, but not a required live dependency.

7. Historical depth policy agreed

Store all reliable history, but use a recent, decayed active estimate. The production-oriented starting point was 180 active days with a 30-45 day half-life, a low-weight slow anchor where available, and old regimes retained for stress rather than equally weighted into today's quote.

8. Architecture separated into data planes

Live quoting was isolated from collection and calibration. The writer consumes a local approved artifact; historical providers and databases never sit on the HTTP quote path.

9. Beta scope reduced

The target became a testnet proof with at most 20 underlyings. Public candleSnapshot history provides about 208 days of hourly data, removing the need for QuickNode, a managed database, or commercial live feeds.

10. Handoff frozen

The approved design, facts, cost envelope, acceptance criteria, and unknown-unknown controls were saved for a new orchestrator to turn into an implementation plan in a fresh session.

Unknown unknowns made explicit

  1. The existing positive-loading model cannot represent negative base correlations between different underlyings.
  2. A band payoff needs a dispersion latent; the current writer treats it as uncorrelated.
  3. Closed TradFi sessions can masquerade as zero returns if candles are forward-filled or aligned naively.
  4. Multi-day returns sampled hourly overlap and can create false confidence about sample size.
  5. Testnet liquidity and behavior do not establish mainnet adverse-selection or profitability.
  6. Old symbols may hide token migrations, stock splits, index changes, DEX remapping, or settlement-reference drift.
  7. Publishing live model inputs immediately could enable quote gaming; transparency should be delayed until resolution.
  8. A rich empirical matrix projected into three factor axes may look stable while discarding economically material structure.
